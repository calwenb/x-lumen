## 前端 UI 升级计划：接入 Element Plus 统一双端风格

### 诊断摘要
两套前端共性问题：**零阴影/零层级、零图标、零过渡动效、博客顶栏无激活态、圆角体系混乱**；另有一个真实 bug：博客端 `tokens.css` 缺失 5 个 token（`--xl-radius`、`--xl-radius-sm`、`--xl-bg-secondary`、`--xl-color-danger/success/warning`）导致 **8 处样式失效**（AI 气泡透明、工作台卡片直角、徽标消失等）。Element Plus ^2.9 已在两个前端 node_modules 中（当前死依赖，零引用），接入成本低。

### 阶段一：依赖与主题基础设施（两个前端同步）
1. 两个前端 `pnpm add @element-plus/icons-vue`（EP 配套图标库）
2. `main.ts` 接入 Element Plus 全量注册 + 全量样式
3. 新建 `src/styles/element-theme.css`：用 CSS 变量把 EP 主题映射到现有 `--xl-*` 体系（`--el-color-primary: #5367e8`、圆角 8px、字体栈等），保证双端同一视觉语言
4. `tokens.css` 扩展：补缺失 token（修复 bug）+ 新增阴影体系（`--xl-shadow-sm/md/lg`）+ 过渡时长 token
5. `index.css`：全局 `:focus-visible` 焦点环、`::selection`、hover 过渡基准

### 阶段二：管理后台全面 EP 化（4 页面 + 侧栏）
| 组件 | EP 化内容 |
|---|---|
| `App.vue` | `el-container/el-aside/el-menu` 布局；品牌加图标；菜单项图标 + 激活态（EP 原生） |
| `LoginPage` | `el-form/el-input/el-button` + 图标 + 错误提示；背景加渐变装饰 |
| `WorkspaceSettingsPage` | `el-form/el-input/el-switch/el-button` + `el-message` 替代 window.alert |
| `ModelConfigPage` | `el-table/el-select/el-input/el-button` + 成功/失败 `el-message` |
| `AuditLogPage` | `el-table/el-input` 筛选/`el-pagination` + 详情 `el-dialog` 替代原生 details |

### 阶段三：博客前端交互组件 EP 化（内容展示保留定制但统一 token）
| 组件 | 改动 |
|---|---|
| `App.vue` 顶栏 | 导航项加 EP 图标 + router-link-active 激活态（淡紫胶囊）；品牌前加 Logo 图形；搜索框 EP 化保留胶囊样式 |
| `LoginPage` | `el-tabs` 登录/注册切换、`el-form/el-input/el-button`，卡片加阴影 |
| `Pagination` | 替换为 `el-pagination`（保留现有 props 接口，最小侵入） |
| `ArticleListPage` | 状态徽标 `el-tag` 语义色；删除确认 `el-message-box`；列表行 hover |
| `ReviewCenterPage` / `ReleasePage` | `el-table` 化 + `el-dialog` 审核详情 + `el-message` 反馈 |
| `AiWritePage` | 输入区 `el-input/el-button` + 模式 `el-radio-group`；修复输入区无底色 bug |
| `ChatPage` | 修复 AI 气泡透明 bug（补底色+弱阴影）；「小光」青绿圆形头像；发送区 EP 按钮 |
| `ArticleDetailPage` | 正文白卡片化+阴影；目录当前章节主色高亮；标签 `el-tag` 胶囊 |
| `SearchPage` / `HomePage` | 文章卡片改白卡片（阴影+hover 抬升）；侧栏标签胶囊化；空态加图标 |
| 编辑器/评论/问答弹窗 | MarkdownEditor 补 token；CommentList/ArticleQaDialog 弹窗 EP 化 + `el-message` |

### 阶段四：原生弹窗替换
将 5 个文件中的 `window.confirm`（删除/审核/发布确认）与 `window.alert` 全部替换为 `el-message-box` / `el-message`（E2E 无 dialog 依赖，已确认安全），消除风格断层。

### 阶段五：验证与收尾
1. `pnpm lint` + `pnpm stylelint` + `pnpm typecheck` + `pnpm build`（两个前端）
2. 跑 `pnpm test`（单测，检查 EP 化是否破坏组件测试）
3. 跑 `pnpm test:e2e`（后端已就绪，E2E 全部基于语义角色断言；重点验证 auth.spec 的 `getByLabel` 与登录流程在 EP 化后仍通过，如失败则调整 EP 组件属性保持语义）
4. 浏览器截图前后对比（重点页面：首页/登录/工作台/聊天/后台设置/模型/审计），确认视觉提升无布局错乱
5. 更新 `docs/frontend/FRONTEND.md`（§10.1 token 清单、EP 接入说明）与 `docs/ai/CHANGELOG.md`

### 明确不做
- 不引入暗色模式（token 注释预留 F-1306，V2 再启用；EP 的 dark css 变量先不接）
- 不改变路由/信息架构/后端接口，全部为前端表现层改造
- 文章卡片、聊天气泡、Markdown 正文等内容展示组件保留定制 CSS（与 EP 统一 token/圆角/阴影），保持博客的内容网站气质
