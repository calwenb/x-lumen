## 1. 产品定位与核心价值

xLumen 是面向个人博主的 AI 内容创作与知识对话平台：前台主页为文章展示页，AI 对话为前台菜单入口（RAG 检索博主文章生成回答并引用来源），文章的创建、编辑、发布、阅读与互动全部在前台完成；AI 直接输出完整文章（输入主题、草稿或完整文章），配合发布审核、知识可靠性校验与摘要、SEO、翻译等增值能力。管理后台（web）仅供管理员进行空间、模型与审计等配置管理。

核心价值：

- **AI 输出可追溯**：所有 AI 生成内容必须能追溯到知识来源（博主文章的 RAG 索引证据）与网络证据，杜绝无依据的"幻觉输出"。
- **内容全生命周期闭环**：输入→AI 写作→审校→审核→发布→反馈→更新，形成可恢复、可审计的完整闭环；文章发布即自动建立 RAG 索引，AI 知识对话（前台菜单入口）与内容增值为两大核心能力线。
- **单人低门槛**：默认一个空间、一个博主即可完成从文章创作到发布更新的全部流程；多租户架构保留，团队协作（成员/角色）在 V2 可选启用。
- **知识持续保鲜**：通过读者纠错、时效检测、知识缺口分析与旧文更新闭环，避免博客内容过期。

产品边界（MVP）：不包含真实支付、外部 CMS 发布、多人实时共同编辑、本地大模型运行与多语言版本；上述能力若进入规划，必须先更新第 5 节功能总表并经 CHANGELOG 记录。

## 3. 核心业务闭环

```text
【主线一：内容创作（前台创作中心）】
输入（主题 / 草稿 / 完整文章）
→ AI 写作（直接输出完整文章）
→ AI 审校（独立模型：严重度/位置/证据/建议）
→ 博主修订（可迭代）
→ 人工审核（双闸门保留，个人博主本人充当编辑角色）
→ 选择可见性（公开 / 私有）→ 立即或定时发布（幂等）
→【发布即索引】自动切片 → Embedding → 激活 RAG 索引（无需人工导入）
→【公开文章】访客访问、评论、点赞、读者纠错
→ 数据分析与时效检测
→ 旧文更新（新版本重新走审核闭环，索引自动更新）
【主线二：AI 知识对话（前台菜单入口）】
用户提问 → RAG 按身份检索文章（访客仅公开已发布；博主全部含私有）→ AI 生成回答并引用来源
└─ 辅助：文章级问答 / 摘要 / SEO / 翻译 / 配图 / 自动标签 / 语音
【主线三：反馈与保鲜闭环】
读者纠错 / 评论 / 时效检测 → 更新建议 → 博主创建旧文更新任务 → 重走主线一闭环
└─ AI 对话未命中问题沉淀为知识缺口 → 建议补写新文章（反哺主线一）
```

> 双核心说明：产品具备两条核心能力线——内容创作（模块六）与 AI 知识对话（模块七）。前台主页为文章展示页（B01），AI 对话（F-0701）为前台菜单入口，基于 RAG 检索博主文章生成回答并引用来源；文章级问答（F-0702）为辅助入口。增值能力（模块八）作用于创作中的文章或已发布文章。
> 阶段映射：AI 写作与审校对应模块六（F-0601/F-0604），AI 对话对应模块七（F-0701/F-0702），审核对应模块九（F-0902~F-0905），发布与公开访问对应模块九/模块二（F-0201~F-0203），反馈对应模块十（F-1001），更新对应模块十一（F-1105），发布即索引对应模块四（F-0402）。

## 4. 内容状态机（文字版）

文章生命周期共 8 个状态：**构思 → 草稿 → 待审核 → 已通过 → 定时发布 → 已发布 → 更新中 → 已下架**。

```text
构思 → 草稿 → 待审核 → 已通过 → 定时发布 → 已发布
                            └→ 已下架（校验版本后可回滚重新发布）
已发布 → 更新中 → 新版本 → 待审核（重新走完整审核闭环）
```

关键规则：

- **已发布版本不可修改**；更新必须创建新版本并重新审核，新版本审核通过前线上保持旧版本。
- 审核期间正文发生变化会使原审核失效（版本校验）。
- 审核、发布、回滚、下架必须校验文章版本，冲突返回 HTTP 409。
- 定时发布到期执行发布幂等检查，重复任务不产生重复公开版本。
- 可见性（公开/私有）是独立于状态的发布属性（F-0307）：私有文章仅博主可见，不进入公开列表、搜索与 URL，但参与索引供博主本人 AI 问答检索。

## 6. 行为规则（MVP）

以下只展开 MVP 阶段必须落地的行为约束；V2/V3 功能的行为详见功能总表对应行，不再重复展开。

- **空间隔离**：所有业务数据按空间隔离（表级 space_id + 接口级空间校验双层），权限变化即时生效。
- **文章可见性**：文章发布时选择公开或私有（F-0307）；私有文章仅博主本人可见，不进入公开列表、搜索与 URL。
- **发布即索引**：文章发布成功自动触发 RAG 索引流水线（F-0402），删除/下架同步移出索引；AI 对话检索按身份过滤（F-0407，访客仅公开已发布、博主全部含私有）。
- **大纲可选确认**：长文场景（研究报告、深度分析）作者可启用大纲确认（F-0602）；默认由 AI 直接输出完整文章。
- **双闸门审核**：发布必须通过 AI 审校（独立模型，F-0604）与编辑人工审核（F-0902）两道闸门，任一未通过不得进入发布队列。
- **职责分离**：作者不能发布；编辑不能审核自己提交的文章（F-0903）；个人空间可关闭强制审核（引用 D9）。
- **驳回三要素**：驳回必须填写原因、问题位置、期望修改（F-0904）。
- **发布幂等**：重复发布任务不产生重复公开版本（F-0905）。
- **引用溯源**：AI 输出引用文章必须带证据（篇名/段落定位），可跳转原文（F-0405）。
- **409 版本冲突**：并发编辑/审核/发布以版本号校验，冲突返回 HTTP 409，禁止静默覆盖。

> 上述规则与功能总表（第 5 节）、内容状态机（第 4 节）共同构成 MVP 行为基线，实现与验收均以此为准；V2/V3 功能行为详见功能总表对应行。

## 7. 接口与实时通信（原则）

- REST 统一前缀 `/api/v1`，统一响应结构（ApiResponse）+ 全局异常 + `requestId` 链路（F-1303）。
- SSE 用于 AI 流式输出（分章节流式，F-0503）与异步任务进度。
- WebSocket 仅用于站内通知（F-1004）。
- OpenAPI 是前后端接口契约唯一来源（决策 D4），前端据此生成 TypeScript 类型。
- 写操作按风险使用业务幂等键与版本号，禁止静默覆盖。

## 8. AI 与外部服务

- **AI 命名**：产品内所有面向用户的 AI 能力（AI 对话、文章级问答、访客助手、AI 写作与审校反馈等）统一称呼为**小光**，界面文案与提示不得使用其他 AI 名称。
- 模型供应商：百炼、DeepSeek，多供应商隔离（F-0501）；按 Writing/Reviewer/问答/摘要/Embedding 场景分别配置（F-0502）。
- 知识来源优先级：**博主文章（RAG 检索证据）> 网络临时证据**；网络内容视为不可信输入。
- 流式输出开始后不得自动切换模型续写；失败后由用户明确发起新任务。
- 降级与熔断：供应商不可用时按场景策略降级（如 Reviewer 切换备用模型），降级原因进入 AI Trace（F-0505）。
- 结构化输出必须通过 Schema 校验；权限、参数、内容安全错误不能通过切换模型绕过。
- AI 输出可靠性要求：引用可溯源、可验证；无法溯源的内容必须明确标注为模型生成而非事实。

## 9. 数据一致性与任务可靠性

- MySQL 保存业务事实、任务、版本、审核、计划与用量；Redis 只保存缓存、会话、限流、短期状态与短临界区锁（决策 D6）。
- 异步任务原则：AI 长任务必须异步执行并展示进度（F-1302），支持有限重试、检查点、取消、死信与人工补偿。
- 幂等：任务处理、事件消费、配额结算均必须幂等；重复回调不得重复结算。
- 事件 Outbox：跨模块反向流程用 RocketMQ + Outbox 保证可靠投递（决策 D3），消费者必须幂等。

## 10. 安全与内容治理

- 认证 Cookie 策略：会话 Cookie 必须 httpOnly + SameSite=Lax；刷新令牌短时效且支持撤销。
- 防枚举：登录、注册、密码重置接口不得暴露账号是否存在（统一延迟与提示）。
- 上传文件校验扩展名、MIME、文件特征、大小与恶意内容；网页内容属于不可信输入，需检测提示词注入；Markdown 渲染必须执行 XSS 清洗。
- 敏感内容治理：密钥、密码与发布凭证不得出现在接口、日志、指标或消息中；高风险操作记录审计日志。

## 12. 完成定义

一个产品功能完成必须同时满足：

1. 用户可以在界面完成正常流程，并能理解失败原因和恢复方式。
2. 权限、租户、版本、幂等和安全约束由后端执行。
3. 前后端接口与 OpenAPI 一致。
4. 正常、空数据、错误、无权限和冲突状态均已处理。
5. 单元测试、集成测试、端到端测试和构建通过。
6. 新增或改变的产品行为已同步更新对应文档。
7. **功能阶段变更必须同步更新本总表与 PROTOTYPE 原型文档**（决策 D10）。
8. **行为变更必须同步更新本文档**（第 6 节及对应章节）。
