# xLumen 知识平台化重构 · 完整设计方案（草案 v0.1）

> 状态：**已确认（2026-08-14）**。本文档为评审稿存档，正式内容以 `docs/` 体系为准（阶段 0 已落地）。
> 更新日期：2026/8/14
> 适用范围：产品定位、概念模型、功能范围、数据模型、界面原型、实施计划。

---

## 0. 变更摘要（TL;DR）

1. **产品定位升级**：由「面向个人博主的 AI 内容创作平台」升级为「多用户知识平台」（改写决策 D9）。
2. **概念统一**：全项目「文章」概念统一改名「知识」（文档、代码、接口、前端文案全量替换，纳入实施计划）。
3. **新增三层组织结构**：空间 → 知识库（公开/私有/授权）→ 多级目录 → 知识；单库单目录。
4. **可见性上移**：文章级公开/私有开关删除，可见性完全由知识库决定（重定义 F-0307）。
5. **目录替代分类**：`category` 废弃，多级目录树接管归属导航；标签（tags）保留。
6. **删库连带回收站**：删除知识库需二次确认，库与库内知识连带进统一回收站（扩展 F-0305）；不可跨库移动，只能复制或重新发布。
7. **排序规则定稿**：知识列表统一按更新时间倒序；目录按名称排序（数据库排序规则）；目录内知识按创建时间正序。
8. **首页知识流按身份聚合**：访客=公开库已发布；登录用户=+自己私有库已发布（🔒 标记）。
9. **RAG 索引按库切分**：`kb_chunk`/`kb_index_version` 增加库维度，AI 检索按可见库集合过滤。

## 1. 背景与动机

- 现状：MVP 已交付 13 个里程碑，知识检索以「单一隐式 RAG 索引 + 文章级可见性」运行（D13 发布即索引、F-0307/F-0407）。
- 问题：①内容只有「分类（平铺字符串）+ 标签」两级扁平组织，缺乏多级归属结构；②「私有的其他知识库」需求无法满足（无知识库实体）；③「文章」一词与「知识平台」定位不符。
- 目标：建立「知识库 → 目录 → 知识」三层体系，成为**人人可建库、可浏览他人公开库**的多用户知识平台，且**知识 = 文章**贯穿全项目。

## 2. 核心概念模型

```
用户（注册即建默认空间，复用 iam_workspace）
 └─ 空间（作者对外身份/主页）
     └─ 知识库 ×N（可见性：公开 / 私有 / 授权可见[V2]；状态：正常 / 回收站）
         └─ 目录树（多级，parent_id 自关联）
             └─ 知识（即原「文章」，复用 cnt_article + 8 状态机）
```

**概念定义：**

| 概念 | 定义 | 关键属性 |
| --- | --- | --- |
| 知识 | 即原「文章」，一篇完整内容 | 复用 cnt_article：8 状态机、版本、审核闭环；单库单目录归属 |
| 目录 | 知识库内的多级组织树 | 父目录引用、名称（按名称排序，数据库排序规则） |
| 知识库 | 内容的容器与**权限边界** | 空间归属、名称、简介、封面、可见性（公开/私有）、授权名单(V2)、回收站状态 |

**重要规则**：草稿/待审核/更新中等未达「已发布」状态的知识，**无论所在库公开与否，仅作者本人可见**；发布之后才按库可见性决定外部可见范围。

## 3. 概念统一：文章 → 知识（全项目，纳入实施计划）

### 3.1 改名原则

- 用户可见的一切文案（页面标题、按钮、提示、导航、AI 输出、审计展示）：「文章」→「知识」。
- 代码标识符与接口：`Article*` → `Knowledge*`（类名、方法、事件、审计常量、缓存 key、URL 路径、前端路由与组件）。
- 存量历史数据（审计日志旧文案、旧缓存 key 失效后自然淘汰）不回溯改写。
- 全仓替换以 grep 清单驱动：`文章|Article|article|ARTICLE` 与 `cnt_article` 逐一核对替换，替换后跑全部门禁回归。

### 3.2 改名范围清单

| 层 | 现状（示例） | 改为 | 策略 |
| --- | --- | --- | --- |
| 文档 | PRODUCT/BACKEND/FRONTEND/PROTOTYPE/README/STATUS/CHANGELOG 中「文章」措辞 | 「知识」 | 文档先行阶段全量替换 |
| 数据库 | `cnt_article` 表及列注释；`kb_chunk`/`kb_index_version` 的 `article_id` 列 | **物理表名改为 `cnt_knowledge`**，注释统一「知识」；`article_id` 列同步改名 `knowledge_id` | 全量改名（含索引/迁移脚本/代码引用） |
| 后端代码 | `ArticleController`/`ArticleQueryDTO`/`PublicArticleController`/`ArticlePublishedEvent`/审计常量 `ARTICLE_PUBLISH` | `KnowledgeController`/`KnowledgeQueryDTO`/`PublicKnowledgeController`/`KnowledgePublishedEvent`/`KNOWLEDGE_PUBLISH` | 全量重命名（IDE rename + 回归） |
| 后端接口 | `/api/v1/articles` 等路径 | `/api/v1/knowledge`（不可数名词） | 是否保留旧路径兼容见开放问题 3.4-② |

| 测试 | 单测/E2E 断言中的 article 措辞与选择器 | knowledge | 随改名同步更新 |
| RAG | `kb_chunk` 注释、事件名、检索接口文案 | 「知识」 | 随阶段 1 同步 |

### 3.3 改名与功能变更的先后关系

概念改名（阶段 1）与知识库功能（阶段 2~5）**分开提交**：先做纯改名回归（不改变行为），再做功能变更，降低评审与回滚难度。

### 3.4 开放问题（已确认，2026-08-14）

1. 数据库物理表名 **`cnt_article` 同步改名为 `cnt_knowledge`**，所有相关引用（索引名、注释、迁移脚本、代码引用）一并修改，不保留旧名。
2. 旧接口路径 `/api/v1/articles` **同步切换为 `/api/v1/knowledge`，不保留兼容期**（前后端同仓同 PR 切换）。
3. 私有库授权名单（`kb_kb_grant`）确认放 **V2**。
4. 回收站保留期默认 **30 天**（空间设置可配置，后续实现）。

## 5. 数据模型设计

### 5.1 新增表

```sql
-- 知识库（F-0308）
CREATE TABLE kb_knowledge_base (
    id            BIGINT PRIMARY KEY,
    workspace_id  BIGINT NOT NULL,          -- 归属空间
    name          VARCHAR(64) NOT NULL,
    intro         VARCHAR(500) DEFAULT '',
    cover         VARCHAR(255) DEFAULT '',  -- 封面（V2 接入 MinIO 前可空）
    visibility    TINYINT NOT NULL DEFAULT 0,  -- 0 私有 / 1 公开
    status        TINYINT NOT NULL DEFAULT 0,  -- 0 正常 / 1 回收站
    deleted_at    DATETIME NULL,            -- 进回收站时间（超期清理依据）
    created_at    DATETIME NOT NULL,
    updated_at    DATETIME NOT NULL,
    KEY idx_kb_ws_vis (workspace_id, visibility)
);

-- 目录树（F-0309，多级 parent_id）
CREATE TABLE kb_directory (
    id         BIGINT PRIMARY KEY,
    kb_id      BIGINT NOT NULL,
    parent_id  BIGINT NOT NULL DEFAULT 0,   -- 0 = 根目录
    name       VARCHAR(64) NOT NULL,          -- 目录名（列表按 name 排序，走数据库排序规则）
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    KEY idx_dir_kb_parent (kb_id, parent_id)
);

-- 私有库授权名单（F-0106，V2）
CREATE TABLE kb_kb_grant (
    id         BIGINT PRIMARY KEY,
    kb_id      BIGINT NOT NULL,
    user_id    BIGINT NOT NULL,
    created_at DATETIME NOT NULL,
    UNIQUE KEY uk_kb_user (kb_id, user_id)
);
```

### 5.2 变更表

| 表 | 变更 |
| --- | --- |
| `cnt_article` | 物理改名为 **`cnt_knowledge`**；`+ kb_id`、`+ directory_id`（单库单目录，索引 `idx_knowledge_kb_dir`）；`- category`（迁目录树）、`- visibility`（迁库级）；tags 保留 |
| `kb_chunk` | `+ kb_id`（检索按库过滤） |
| `kb_index_version` | `+ kb_id`（索引版本按库） |

### 5.3 约束

- 单库单目录：`cnt_article.kb_id + directory_id` 归属唯一；目录必须属于知识所属的库。
- 知识进回收站：随库连带（库删除时知识随库软删）；单独删除知识也进回收站。
- 公开列表/搜索/检索的过滤条件由 `status=已发布 AND 库可见性=公开` 组成（替代原 `visibility=1`）。

## 6. 可见性与权限矩阵

| 库类型 | 谁能浏览库/看列表 | 谁能读知识 | 谁能检索到（AI 对话/搜索） | 检索得到什么 |
| --- | --- | --- | --- | --- |
| 公开库 | 所有人 | 所有人 | 所有人 | 库内已发布知识 |
| 私有库 | 仅库主 | 仅库主 | 仅库主 | 库内已发布知识（RAG 索引仅覆盖已发布版本，草稿不入索引） |
| 授权私有库（V2） | 授权名单 | 授权名单 | 授权名单 | 库内已发布知识 |

- **库切换器**可选集合 = 所有公开库 + 自己的公开/私有库 + 被授权库（V2）。
- **首页知识流**（按身份聚合）：访客 = 所有公开库已发布知识；登录用户 = 公开库已发布 + 自己私有库已发布（🔒 标记）；统一按更新时间倒序。
- **知识库发现页**：所有公开库的卡片墙（封面/名称/简介/知识数），登录后附「我的知识库」入口。
- 库可见性变更即时生效：公开→私有，库内已发布知识立即退出公开列表/搜索/公开检索；反之立即进入。

## 7. 行为规则

### 7.1 发布流程

```
… → AI 审校 → 人工审核（双闸门保留）
→ 选择目标知识库 + 选择目录（或新建）→ 立即/定时发布（幂等保留）
→ 发布即索引（按库切分）
```

- 发布弹窗删除「公开/私有」开关（F-0307 废止），提示语随库类型变化：「公开库的知识发布后所有人可见并进入知识列表」/「私有库仅自己可见」。
- 没有可用库时引导「+ 新建知识库」。

### 7.2 删除与回收站

- 删除知识库：二次确认（明示「库内 N 篇知识将一并移入回收站」）→ 库与库内知识连带软删 → 可整体恢复 / 彻底删除（物理级联删知识）/ 超期（默认 30 天，可配置）自动清理。
- 单篇知识删除：进回收站，可恢复回原库原目录。
- 连带处理：删除知识库/知识时同步取消关联的定时发布任务并作废未决审核记录（幂等）。
- 恢复冲突：知识恢复时原目录已删除 → 恢复至该库根目录（目录可空）；原库已彻底删除 → 提示「原库不存在」，只能彻底删除或复制到现有库。
- 实现（已确认）：回收站用独立软删标记列（`recycle_status` + `deleted_at`），**不扩展 8 状态机**——状态机是发布审核闭环概念，回收是删除语义。
- 回收站页：Tab 分「知识库 / 知识」，显示删除时间与剩余天数；彻底删除为红色操作 + 二次确认。

### 7.3 跨库规则

- 同库内换目录：允许。
- 跨库移动：**不提供**；只能「复制为新知识」或「在新库重新发布」（避免公开↔私有可见性意外切换）。

### 7.4 排序规则（定稿）

| 位置 | 规则 |
| --- | --- |
| 知识列表（首页流/库内列表/创作中心管理列表） | 统一按**更新时间倒序**（无创建/更新切换按钮） |
| 目录树 | 按目录名排序（数据库排序规则，ORDER BY name） |
| 目录内知识 | 按**创建时间正序**（章节式阅读顺序） |

口径：创建时间 = 首次发布；更新时间 = 最近一次新版本发布。

### 7.5 AI 检索范围

- AI 对话（AI小光）检索范围 = 提问者可见库集合；按库过滤 + 知识状态过滤（替代 F-0407 文章级过滤）。
- 详情页/库页发起问答时默认锁定当前库，可切「全部可见库」。
- Noop 降级（Milvus 未装）行为不变：明确回复「未检索到任何相关知识证据」。

## 9. RAG 索引与 AI 检索变化

- 索引流水线不变（清洗→切片→幂等→Embedding→写向量→激活），仅 `IndexRequestDTO` 与落库元数据增加 `kbId` 维度。
- 检索请求携带「可见库集合」（由身份与授权推导）→ VectorStore 过滤条件从 `workspace_id + visibility` 变为 `workspace_id + kb_id IN (可见库) + 知识状态`。
- Noop 降级行为不变（返回空 + 明确无依据回复）；Milvus 就绪后过滤字段同步增加 kb_id。
- 知识缺口分析（F-1103，V3）统计口径随库维度细化。

## 10. 存量数据迁移方案

1. 物理表改名：`cnt_article` → `cnt_knowledge`（含索引与引用同步），在迁移脚本内与结构变更一并执行。
2. 每空间自动创建两个默认库：**「默认公开库」**（公开）与 **「默认私有库」**（私有）。
3. 现有知识按原 `visibility` 值归入：`1→默认公开库`、`0→默认私有库`。
4. 原 `category` 字段值：在每个库内平铺为同名一级目录（去重），知识挂入对应目录；无 category 的知识挂根目录（目录可空）。
5. 迁移脚本幂等（迁移标记 + 事务），执行后校验：每篇知识有且仅有一个库/目录归属、公开库知识数 = 原公开知识数。
6. 测试种子数据（公开 3 + 草稿 1 + 私有 1）随迁移脚本同步调整，不进初始化 SQL。

## 13. 风险与开放问题

**风险：**

1. **改名波及面大**：接口路径、E2E 断言、审计常量、缓存 key（`xlumen:article:*`）全部联动，阶段 1 必须纯改名、零行为变更，靠全部门禁回归兜底。
2. **多用户安全面**：库越权（他人私有库）、公开库检索泄露私有知识——权限过滤必须后端强制执行 + 专项测试。
3. **Milvus 未装**：按库过滤的向量侧逻辑先落元数据与查询构造，Noop 降级行为保持一致，Milvus 就绪后自动生效。
4. **审计历史**：旧 `ARTICLE_PUBLISH` 类型日志保留原值，新增 `KNOWLEDGE_PUBLISH`，展示层兼容两种。
5. **回收站容量**：超期清理任务需调度（沿用 PublishJob 模式），默认保留 30 天可配置。

**开放问题（全部已确认）：**

1. ✅ `cnt_article` 物理表名同步改为 `cnt_knowledge`（全量改名）。
2. ✅ 旧 `/api/v1/articles` 路径直接切换为 `/api/v1/knowledge`，不保留兼容期。
3. ✅ 私有库授权名单（`kb_kb_grant`）放 V2。
4. ✅ 回收站保留期默认 30 天（可配置）。

## 14. 验收标准

1. 用户可完成：建库 → 建目录 → 写知识 → 发布到库 → 他人/自己按身份浏览与检索全流程。
2. 权限、租户、库可见性、版本、幂等约束全部由后端执行；公开库知识对访客可见，私有库知识对外不可见、不可检索。
3. 首页知识流按身份聚合正确（访客无私有、登录含自己私有 🔒）；排序规则三处（列表更新时间倒序/目录按名称/目录内创建正序）生效。
4. 删除知识库连带进回收站，可恢复/彻底删除；跨库移动入口不存在。
5. 全项目「文章」措辞清零（grep 校验仅历史审计数据允许保留）。
6. 单测、集成、E2E、构建全绿；文档与代码一致（决策 D7）。
